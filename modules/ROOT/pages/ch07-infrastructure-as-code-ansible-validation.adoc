== 7.1 Introduction: The 2:00 AM Configuration Nightmare

A banking enterprise requires a critical QoS and VLAN update across 450 branch routers before morning opening. Six engineers divide spreadsheets and enter changes via SSH. By 4:00 AM, four routers fail to accept commands due to syntax variances, three routers are partially configured and drop traffic, and nobody knows which devices match the intended policy.

Infrastructure as Code (IaC) eliminates configuration drift by treating network configurations as version-controlled code, enforced through idempotent automation engines.

== 7.2 The Philosophy of Infrastructure as Code

image::ch07/g7-1-iac-idempotency-loop.png[Infrastructure as Code Idempotency and Reconciliation Loop]

* **Idempotency:** Executing a configuration task once applies the required changes; executing it again produces zero changes and zero errors.
* **Configuration Drift:** The gradual divergence of live network configurations from intended baselines due to unrecorded manual edits.

[source,yaml]
----

  hosts: switches
  gather_facts: no
  tasks:
    - name: Ensure VLAN 100 Exists

        lines:
          - name USERS
        parents: vlan 100
----

== 7.8 Key Terms

idempotent:: A quality of an operation that guarantees the same system state whether applied once or multiple times.
Ansible Control Node:: The system hosting Ansible from which automation tasks and playbooks are executed against managed inventory.
pyATS:: Cisco's Python Automated Test System; a test framework used to validate device state through structured parsing.
