== 8.1 Introduction: Beyond the Human Interface

Parsing human-readable console text via screen-scraping breaks whenever firmware updates adjust whitespace or punctuation. True network programmability separates the data model from the transport protocol, allowing software to query and configure network devices with mathematical precision.

Model-Driven Programmability uses standardized YANG schemas, NETCONF over SSH, and RESTCONF over HTTPS to manage devices programmatically.

== 8.2 YANG Data Modeling: The Schema of the Network

image::ch08/g8-1-model-driven-stack.png[Model-Driven Programmability Stack: Transport, Protocol, Model, and Encoding]

image::ch08/g8-2-yang-tree-hierarchy.png[YANG Model Tree Hierarchy: Containers, Lists, Leaves, and State Data]

YANG defines the data structure for devices:
* `leaf`: Single value (e.g., interface name).
* `container`: Grouping of related nodes.
* `list`: Collection of entries identified by a unique key.
* `config true` vs `config false`: Distinguishes configurable settings (`rw`) from read-only operational telemetry (`ro`).

== 8.3 NETCONF: Network Configuration Protocol

.Video 8.2: NETCONF in Action: Executing XML RPCs with Python and ncclient
[video, width=800, height=450]
video::v8-2-netconf-ncclient.mp4[poster=v8-2-poster.png, captions=v8-2-captions.vtt]

image::ch08/g8-3-netconf-architecture-rpc.png[NETCONF Protocol Architecture: SSH Port 830, RPCs, and XML Filters]

[source,python]
----
from ncclient import manager

router = {
    "host": "10.10.20.48", "port": 830,
    "username": "developer", "password": "CiscoPassword123!",
    "hostkey_verify": False
}

netconf_filter = """
<filter xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces"/>
</filter>
"""

with manager.connect(**router) as m:
    response = m.get_config(source="running", filter=netconf_filter)
    print(response.xml)
----

== 8.4 RESTCONF: RESTful Model-Driven Management

.Video 8.3: RESTCONF in Practice: Managing IOS-XE Devices with HTTP and yang-data+json
[video, width=800, height=450]
video::v8-3-restconf-practice.mp4[poster=v8-3-poster.png, captions=v8-3-captions.vtt]

image::ch08/g8-4-restconf-uri-mapping.png[RESTCONF URI Path Mapping and HTTP Verbs]

RESTCONF exposes YANG models over HTTPS using standard HTTP verbs and JSON formatting:
[source,python]
----
import requests

url = "https://10.10.20.48/restconf/data/ietf-interfaces:interfaces"
headers = {"Accept": "application/yang-data+json"}
response = requests.get(url, headers=headers, auth=("developer", "CiscoPassword123!"), verify=False)
print(response.json())
----

== 8.8 Key Terms

YANG:: Yet Another Next Generation; a data modeling language used to define configuration and state data for network devices.
NETCONF:: Network Configuration Protocol; an IETF protocol operating over SSH port 830 using XML RPCs to manage configurations.
RESTCONF:: An IETF protocol operating over HTTPS using standard HTTP verbs and JSON/XML payloads to access YANG-modeled data.
ChatOps:: An operational model that connects people, tools, process, and automation into a transparent workflow mediated by chat platforms.
