== 6.1 Introduction: "It Worked on My Laptop"

An engineer develops an interface audit script on their workstation. When copied to a production jump host to run as a nightly cron job, it fails immediately because the server runs Python 3.6 instead of 3.10, lacks required libraries, and has different SSL cipher suites.

Packaging applications into immutable, lightweight Docker containers and running automated tests in Continuous Integration (CI) pipelines eliminates environment discrepancies and guarantees predictable deployment.

== 6.2 Deployment Models: From Metal to Containers

image::ch06/g6-1-deployment-models-spectrum.png[Deployment Spectrum: Bare Metal, VMs, Containers, and Edge]

* **Bare Metal:** Single OS tied to hardware; low density, slow provisioning.
* **Virtual Machines:** Hypervisor virtualizes hardware; runs complete guest operating systems; strong isolation but high memory overhead.
* **Containers:** Share the host Linux kernel; isolate processes and filesystems via Linux namespaces and cgroups; instant startup and minimal footprint.

=== Sample Multi-Stage Dockerfile
[source,dockerfile]
----
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY src/ ./src/
EXPOSE 5000
CMD ["python", "src/main.py"]
----

== 6.4 Continuous Integration (CI) Pipelines

CI pipelines automatically build code and run unit tests on every Git push, preventing defective scripts from reaching production.

.Video 6.3: Automating Quality: Building a Continuous Integration (CI) Pipeline with GitHub Actions
[video, width=800, height=450]
video::v6-3-ci-pipeline-actions.mp4[poster=v6-3-poster.png, captions=v6-3-captions.vtt]

image::ch06/g6-4-ci-pipeline-architecture.png[Continuous Integration Pipeline Architecture]

[source,yaml]
----
name: Network Automation CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
        with: { python-version: "3.11" }
      - run: pip install -r requirements.txt
      - run: python -m unittest discover -s tests
----

=== Defending Against Command Injection
Avoid passing unsanitized user strings directly into system shells:
[source,python]
----
# INSECURE: Vulnerable to command injection
import os
os.system(f"ping -c 1 {user_ip}")

# SECURE: Parameterized execution without shell expansion
import subprocess
subprocess.run(["ping", "-c", "1", user_ip], check=True)
----

== 6.8 Key Terms

container:: A standardized, standalone unit of software packaging code and all dependencies.
Continuous Integration (CI):: The practice of automating the building and testing of code every time a team member commits changes to version control.
command injection:: An attack where arbitrary commands are executed on the host operating system via an insecure application input.
