== 2.1 Introduction: Escaping the Vendor Documentation Maze

Enterprise network engineers are often tasked with automating unfamiliar hardware under tight deadlines. Searching search engines or forum posts for automation snippets frequently yields outdated code written against deprecated API endpoints or containing insecure credential handling.

To build reliable automation, engineers must rely on vendor-authoritative resources, interactive API explorers, and dedicated hardware sandboxes. Cisco DevNet provides a comprehensive ecosystem of learning labs, code exchanges, and live sandbox topologies to prototype solutions safely.

== 2.2 The Cisco DevNet Ecosystem Architecture

Cisco DevNet (`developer.cisco.com`) is Cisco's unified platform for developer tools, APIs, software development kits, and community learning.

image::ch02/g2-1-devnet-four-pillars.png[The Four Core Pillars of Cisco DevNet]

DevNet is organized around four core services:
1. **Learning Labs:** Modular, hands-on tutorials covering Python, REST APIs, and platform SDKs.
2. **DevNet Sandboxes:** Free, cloud-hosted lab environments spanning physical and virtual network infrastructure.
3. **DevNet Code Exchange:** A curated, Cisco-vetted directory of open-source automation scripts and repositories.
4. **Community & Support:** Discussion forums, Webex developer spaces, and technical support tickets.

== 2.3 DevNet Sandboxes: Always-On vs. Reservable

Testing automation scripts against production routers can cause outages. DevNet Sandboxes provide safe environments to test code before deployment.

.Video 2.2: Sandboxes Demystified: Always-On vs. Reservable VPN Topologies
[video, width=800, height=450]
video::v2-2-sandboxes-demystified.mp4[poster=v2-2-poster.png, captions=v2-2-captions.vtt]

image::ch02/g2-2-sandbox-taxonomy.png[Always-On vs Reservable DevNet Sandboxes]

* **Always-On Sandboxes:** Multi-tenant environments accessible 24/7 over public HTTPS. Ideal for quick API queries (GET requests) and learning API structure without VPN setup.
* **Reservable Sandboxes:** Dedicated, private virtual network topologies scheduled for dedicated time blocks. Access is provided via AnyConnect VPN, granting full administrative privileges and persistent write access.

image::ch02/g2-3-reservable-vpn-topology.png[Connecting to a Reservable DevNet Sandbox via AnyConnect VPN]

=== Security Red Flags in Automation Scripts
* **Hardcoded Credentials:** Storing plain-text API keys or passwords in scripts committed to source control.
* **Disabled TLS Validation:** Setting `verify=False` in Python `requests`, exposing network transactions to man-in-the-middle attacks.
* **Deprecated Endpoints:** Utilizing API versions marked for retirement (e.g., using `/api/v1/` when `/api/v2/` is the active standard).

=== User Stories and Acceptance Criteria

You will deconstruct the customer requirements into Agile user stories:
* *User Story:* "As a network operations engineer, I want an automated Python audit tool to verify VLAN configurations across campus distribution switches so that manual errors are eliminated during maintenance windows."
* *Acceptance Criteria:*
  * Given a list of target switch IP addresses in YAML format.
  * When the audit script executes against the target devices.
  * Then it verifies VLAN 10, 20, and 99 exist and returns a structured JSON summary report.

== 2.8 Key Terms

Always-On Sandbox:: A shared, public cloud lab environment providing immediate, read-only API access without scheduling.
Reservable Sandbox:: A private, isolated network pod scheduled on-demand and accessed via AnyConnect VPN with administrative rights.
user story:: A short, simple requirement written from the perspective of an end user specifying what they need and why.
acceptance criteria:: Measurable, verifiable conditions that a software component must satisfy to be deemed complete.
